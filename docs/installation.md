# Installation

## Requirements

- macOS or Linux with zsh.
- [Bun](https://bun.sh/docs/installation) 1.4 or newer, available on `PATH`.
- A configured model provider: either an existing Pi profile or a provider API key. See [configuration](configuration.md).

Bun runs TypeScript directly; cmdhelp has no separate build step and does not require a separate Node installation.

## Install from npm

```sh
bun add -g @abzy128/cmdhelp
cmdhelp --version
```

Make sure the directory printed by `bun pm bin -g` is on `PATH` (normally `~/.bun/bin`). Alternatively, with npm installed:

```sh
npm install -g @abzy128/cmdhelp
```

For npm installations, put `$(npm prefix -g)/bin` on `PATH` as well as Bun's executable directory. Installing through npm does not install Bun; the CLI requires Bun 1.4+ at runtime.

## Install from a checkout

Choose any directory in which to keep the application:

GitHub access is required while the repository is private.

```sh
git clone git@github.com:abzy128/cmdhelp.git
cd cmdhelp
bun install --frozen-lockfile
bun link
cmdhelp --version
```

`bun link` registers the checkout and exposes its `cmdhelp` executable in Bun's binary directory. Keep the checkout in place. To find the global executable directory, run `bun pm bin -g` and make sure that directory is on `PATH`.

If GitHub SSH is not configured, use the HTTPS clone URL with your normal GitHub authentication:

```sh
git clone https://github.com/abzy128/cmdhelp.git
```

## Enable zsh shortcuts

Add this line once to `${ZDOTDIR:-$HOME}/.zshrc`, after your other plugins:

```zsh
eval "$(cmdhelp init zsh)"
```

Also run it in your current shell, or open a new terminal. `cmdhelp init zsh` prints a quoted source statement pointing to the installed integration file; it does not modify your shell configuration.

If your shell configuration is generated by a dotfile manager, add the line to that manager's source configuration.

To change the launch shortcuts, put your bindings after the init line:

```zsh
bindkey '^X^G' _cmdhelp_suggest
bindkey '^X^E' _cmdhelp_explain
```

To remove a default binding before replacing it, use `bindkey -r '^X^G'` or `bindkey -r '^X^E'`. Check a candidate sequence with `bindkey 'sequence'` before assigning it.

## Configure a model

Follow the [configuration guide](configuration.md), then run:

```sh
cmdhelp doctor
cmdhelp explain 'printf "%s\n" hello'
```

`doctor` checks configuration and the local model catalog without sending an inference request. The explanation command verifies a live request and may incur usage with your provider.

## Update

For a registry installation, use the same package manager you installed with:

```sh
bun add -g @abzy128/cmdhelp@latest
# Or:
npm install -g @abzy128/cmdhelp@latest
```

From the checkout:

```sh
git pull --ff-only
bun install --frozen-lockfile
```

If you move the checkout, run `bun link` again from its new location and open a new shell. Configuration stays outside the repository.

## Uninstall

Remove the init line from your shell configuration. For a registry installation:

```sh
bun remove -g @abzy128/cmdhelp
# Or:
npm uninstall -g @abzy128/cmdhelp
```

For a checkout installation, run from the checkout:

```sh
bun unlink
```

Open a new shell to discard the loaded widgets. You can then remove the checkout and, optionally, your `cmdhelp/config.json` file. Do not remove Pi's profile or credentials; they may be shared with other applications.

## Verification

```sh
bun run check
bun test
zsh -n shell/cmdhelp.zsh
```

The shell integration test needs a pseudo-terminal. On macOS:

```sh
script -q /dev/null zsh test/widget.zsh
```

On Linux:

```sh
script -qec 'zsh test/widget.zsh' /dev/null
```

These tests use fixtures, make no model requests, and check cancellation, failure handling, literal insertion, and cursor restoration.

## Troubleshooting

- **`cmdhelp` or `bun` not found:** check `PATH`, Bun's executable directory, and your package manager's global executable directory. For checkout installs, run `bun link` again.
- **Shortcut does nothing:** check `bindkey '^X^G'` and `bindkey '^X^E'`. Another plugin or your terminal may intercept them. Source the integration after plugins or choose other bindings.
- **No model configured / unavailable model:** run `cmdhelp doctor`, then check the [configuration guide](configuration.md). Model IDs must exist in the SDK's catalog or your Pi profile's cache.
- **Expired or rejected credentials:** open Pi with the same profile and sign in again using `/login`.
- **Request timeout:** increase `timeoutMs` or select a faster model. Escape cancels a request and returns to the original shell input.
